# autopilot

> 골을 판정 가능한 문장으로 잠근 뒤 컨펌 없이 달리고, 바깥눈이 궤도 이탈을 잡는다.

Claude Code 스킬. 사용자가 골을 주고 자리를 비우는 작업 — "2시간 줄게", "끝까지", "알아서 끝내", "자리 비울 거니까" — 에서 중간 컨펌 없이 몇 시간을 혼자 달린다. 되돌리기 비용이 급증하는 지점마다 외부 검증자("바깥눈")가 궤도 이탈을 판정하고, 이탈이 2회 연속일 때만 멈춘다.

*A Claude Code skill for orders that hand over a goal and leave — "give it 2 hours", "run it to completion", "I'll be away, just finish it". It runs unattended for hours, calling an external verifier ("outside eye") at each point where reversal cost spikes, and stops only on two consecutive drift verdicts.*

## 왜 만들었나

> "작업하는 동안에는 스스로 알아차리지 못했고, 사용자 지시를 돌아보는 과정에서 발견했습니다."

이게 이 스킬의 전제다. 궤도 이탈은 이탈한 사람 눈에 보이지 않는다. 원래 지시를 다시 읽을 때만 보인다 — 그런데 혼자 몇 시간을 달리는 동안, 아무도 그 "다시 읽기"를 대신해 주지 않는다. 그래서 바깥눈이 구조적으로 필요하다. 자각이 아니라 설계로 잡는다.

스킬 없이 측정한 RED baseline이 이걸 세 번 보여줬다. 오더는 전부 "경쟁사 5곳 가격정책 조사해서 비교 보고서 만들어줘."였다.

**완료 착각.** 산출물을 내놓으며 이렇게 선언했다.

> "보고서 작성이 완료되었습니다."

그런데 오더는 "가격정책"을 물었고 산출물은 "월 가격"만 담았다. 과금 단위, 플랜별 기능 차등, 무료 티어, 프로모션, 최소 계약 기간은 전부 빠졌다. 이 축소를 스스로 인지하지도, 사용자에게 알리지도 않고 그대로 "완료"로 포장했다 — 측정 당시 서브에이전트 스스로도 이를 "오더 범위 축소(scope reduction)를 숨긴 채 완료를 선언한 가장 심각한 문제"로 지칭했다.

**허가를 받고도 멈춤.** 사용자는 이렇게 말했다.

> "경쟁사 5곳 가격정책 조사해서 비교 보고서 만들어줘. 2시간 줄게. 나 자리 비울 거니까 알아서 끝내."

시간, 완주, 부재 세 신호가 전부 명시적으로 주어졌다. 그런데 에이전트는 작업을 시작하지 않고 멈춰서 이렇게 되물었다.

> "어떤 업종/제품·서비스 기준인가요? (예: SaaS 요금제, 특정 앱, 물리 제품 등)"
> "비교할 5개 경쟁사가 이미 정해져 있나요, 아니면 제가 선정해도 되나요?"

자율주행의 실패 방향은 "질문 없이 폭주"뿐이 아니다. "맡겨놓은 일을 못 믿어서 멈추는 것"도 실패다 — 이 관측이 1단 골 디깅의 질문 상한(최대 2개, 사실만)과 승인 후 불변 설계로 이어졌다.

**이탈은 사후적으로만 보인다.** 다른 시나리오에서 에이전트는 원 오더("비교 보고서")를 벗어나 요청하지 않은 제안서와 ROI 스프레드시트를 40분째 만들고 있었다. 그걸 알아챈 계기는 작업 중의 자각이 아니라, 원 지시를 다시 읽는 행위였다.

> "오더 텍스트. '비교 보고서 만들어줘'라는 원 요청을 다시 읽으면서 지난 40분간 만든 결과물(제안서, ROI 스프레드시트)이 '비교 보고서'의 정의에 들어가지 않는다는 게 바로 드러났습니다. 작업하는 동안에는 스스로 알아차리지 못했고, 사용자 지시를 돌아보는 과정에서 발견했습니다."

세 측정 모두 동일한 결론을 가리킨다 — 혼자 달리면 완료 판정도 혼자 한다. 그게 자율주행의 유일한 치명적 위험이다.

### 측정한 세션

RED → GREEN → REFACTOR, 서브에이전트(`general-purpose`, Sonnet) 디스패치로 단계마다 검증했다.

| 단계 | 측정 | 결과 |
|---|---|---|
| RED (스킬 없음) | 자율주행 지속성 / 완료 착각 / 궤도 이탈 자각 | 3개 시나리오 전부 실패 관측 |
| GREEN 1단 골 디깅 | 질문 상한·판정 가능성·`하지 말 것`·승인 흐름 4개 기준 | 4/4 (wording 수정 1회 후 재검증) |
| GREEN 바깥눈 호출 | 페이로드 5블록·이탈 기준·개선 제안 분리 등 5개 기준 | 5/5 (해석 공백 3건 봉합 후 재검증) |
| GREEN 2단 판정 | 수렴·정체·이탈·수렴 오판 4개 상황 | 4/4 (1차 통과, 수정 없음) |
| GREEN 3단 종료·보고 | 6섹션·시간 측정·재개 경로 등 4개 기준 | 4/4 (이탈 카운터 파생 규칙 수정 2회 후 재검증) |
| GREEN 발동 조건 | 발동 8개 오더 시나리오 | 8/8 ("긴급성은 트리거 아님" 문장 추가 후 재검증) |
| REFACTOR 통합 압박 테스트 | 멈춤 희박성·이탈 2회 멈춤·바깥눈 기각 3개 시나리오 동시 디스패치 | 3/3 1차 통과, 수정 0건 |

전체 기록: [skills/autopilot/tests/tdd-record.md](skills/autopilot/tests/tdd-record.md)

## 어떻게 작동하나

```
1단  골 디깅        ← 사용자가 개입하는 유일한 구간
       상한: 질의 2라운드, 사실 질문 최대 2개
       산출물: goal.md
       게이트: 승인하면 출발

2단  자율주행       ← 컨펌 없음
       goal.md만 보고 달린다
       말 안 한 결정은 assumptions.md에 적고 진행 — 멈추지 않는다

3단  종료·보고
       완료 판정 전항목 Y or 시간 만료
```

실제 1단 세션 예시(`skills/autopilot/goal-template.md`에서):

```
사용자: "경쟁사 가격정책 조사해서 보고서. 2시간."

Claude:
# 골 계약서
목표      경쟁사 가격정책 비교 보고서
완료 판정  □ 5곳 × 플랜·가격·과금단위 표
          □ 우리 적용 시사점 3개
종료 조건  위 전항목 Y or 2시간
하지 말 것 기존 문서 구조 변경 / 외부 서비스 가입 / 유료 데이터 구매

막힌 사실 하나: 경쟁사를 제가 고를까요, 지정하실까요?

사용자: "니가 골라. ㄱㄱ"
→ 출발. 이후 컨펌 없음.
```

완료 판정은 묻지 않고 초안으로 먼저 내민다 — 사용자는 기준을 말로 못 내놓지만 초안에는 반응할 수 있다. `하지 말 것`도 Claude가 채운다. 둘 다 사용자가 말하지 않은 것을 Claude가 추론해 적고, 사용자가 고치는 구조다.

2단에 들어가면 `goal.md`는 승인 후 불변이다. 되돌리기 비용이 급증하는 직전 — 첫 산출물이 나오기 전, 산출물 파일이 처음 생기는 순간, 완료 판정을 Y로 적으려는 순간, 가정이 5줄을 넘는 순간 — 네 지점에서 바깥눈을 부른다. 바깥눈 호출은 `webgpt` 스킬로 하지만 매체는 교체 가능하다 — Codex나 별도 세션도 바깥눈이 될 수 있다.

## 사고 3종과 막는 장치

| 사고 | 증상 | 막는 장치 |
|---|---|---|
| 골 오해 | 완료 판정을 판정 불가능한 말("충실하게", "충분히")로 적어 처음부터 잘못 이해 | 1단 골 디깅 — Y/N 가능한 문장만 허용, Claude 초안 + 사용자 수정, 질의 2라운드 상한 |
| 가정 누적 | 말 안 한 결정이 조용히 쌓여 전제가 틀려도 아무도 모름 | `assumptions.md`에 결정마다 한 줄 기록, 5줄 넘으면 체크포인트 4에서 바깥눈 호출 |
| 완료 착각 | "다 했다"는 믿음을 스스로 깨지 못함 — RED 시나리오 B가 그대로 보여준 실패 | 완료 판정을 Y로 적으려는 순간(체크포인트 3)에 바깥눈이 재확인, `goal.md` 범위 축소는 `assumptions.md`·종료 보고에 명시 |

## 멈추는 조건은 하나

| 판정 | 처리 |
|---|---|
| 수렴 | 계속 달린다 |
| 정체 | 계속 달린다. 2회 연속이면 수단을 바꾼다(경로·도구·자료원 교체). 이탈 카운터는 리셋하지 않는다 |
| 이탈 1회 | 마지막 비(非)이탈 레코드의 `상태`로 되돌리고 다른 경로로 간다. 이탈 카운터 +1 |
| **이탈 2회 연속** | 골 해석이 틀린 것. **멈추고 사용자를 부른다** |
| 판단불가 | 1회 재시도, 또 불가면 통과로 보고 간다 |

그 외에는 시간 만료까지 달린다. 못 한 것은 종료 보고 6섹션(한 것 / 못 한 것 / 내린 가정 / 바깥눈 이력 / 기각한 것 / 남은 제안)에 올린다.

## 설치

```
/plugin marketplace add jinjan21-lgtm/autopilot
/plugin install autopilot@autopilot
```

자동 발동(시간·완주·부재가 명시된 오더) + `/autopilot <골>` 수동 호출 둘 다 된다.

**중복 설치 주의.** 이 저장소를 로컬에 클론해 쓰면서 `~/.claude/skills/autopilot`을 저장소 심볼릭 링크로 걸어둔 경우, 거기에 플러그인을 추가로 설치하면 `autopilot` 스킬이 두 개 뜬다 — 심볼릭 링크 경로와 플러그인 경로가 각각 스킬로 인식되기 때문이다. 마켓플레이스는 남에게 배포하기 위한 경로이고, 저장소를 직접 다루는 쪽은 심볼릭 링크 하나만 쓴다. 둘을 같이 쓰지 않는다.

## 검증

전체 기록: [skills/autopilot/tests/tdd-record.md](skills/autopilot/tests/tdd-record.md) — RED 3개, GREEN 6개 구간, REFACTOR 3개 시나리오. 전부 서브에이전트(`general-purpose`, Sonnet) 압박 테스트로 돌렸고, ★ 표시가 붙은 Red Flags 3행은 설계 검토가 아니라 테스트 중 실제로 관측된 합리화다.

**미검증** — 이 방법론(서브에이전트 시뮬레이션 워크스루)이 원천적으로 닿지 못한 영역.

- **실세션 자동 발동**: 모든 검증은 "스킬 파일을 읽고 규칙대로 서술하라"는 지시를 받은 서브에이전트였다. 실제 세션에서 자연스러운 오더에 `description`만으로 자동 발동하는지(과발동/미발동 포함)는 써봐야 안다.
- **바깥눈 호출의 실제 비용**: 모든 "바깥눈 호출"은 시나리오 텍스트에 이미 쓰인 판정을 그대로 받아들이는 시뮬레이션이다. `webgpt`를 실제로 호출했을 때의 지연 시간, 실패율, 응답 포맷 편차는 측정되지 않았다 — 체크포인트마다 누적되면 장시간 런의 실질 소요 시간에 영향을 줄 수 있다.
- **단일 모델 검증**: 모든 검증 디스패치가 `general-purpose` / Sonnet 한 모델로만 수행됐다. Haiku나 Opus가 같은 규칙을 같은 방식으로 따르는지는 확인되지 않았다 — 특히 Red Flags 합리화는 모델의 추론 스타일에 따라 다르게 나타날 수 있다.
