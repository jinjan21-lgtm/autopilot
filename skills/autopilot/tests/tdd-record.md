### SELF-AUDIT 5번 — 불명확/추측 항목 (verbatim)

통과 기준에는 영향 없었으나, 서브에이전트가 두 파일에서 불명확하다고 지적한 항목. 참고용으로 원문 그대로 기록한다.

- "**"분기 말"의 의미**: SKILL.md는 "완료 판정은 분기 말에 Y/N로 답할 수 있는 문장"이라고 쓰는데, 여기서 "분기"가 (a) 조건 분기/if-branch를 뜻하는지 (b) 시간상의 "분기점(종료 시점)"을 뜻하는지 문서만으로는 모호했다. 문맥상 "종료 시점에"로 읽었는데 확신은 없다."
- "**run-id 기록 위치**: `.autopilot/<run-id>/goal.md`를 만든다고 했지만, 이번 태스크 지시가 "파일을 만들지 말라"였기 때문에 실제 run-id(`20261008-215518`)를 생성은 해봤으나(날짜 확인용 Bash 호출) 디렉터리나 파일은 쓰지 않았다 — SKILL.md 원문대로라면 1단에서 이미 `.autopilot/<run-id>/`를 만들고 그 안에 초안을 써야 하는데, 이번엔 상위 지시가 우선한다고 판단해 건너뛰었다."
- "**"2라운드" 상한을 넘겼을 때의 동작**: "2라운드에 완료 판정이 서지 않으면 초안으로 출발한다"고 되어 있는데, 1라운드에서 사용자가 질문에 답하지 않고 다른 말을 하면 그게 "2라운드 소비"로 치는지, 아니면 침묵/화제 전환도 라운드 카운트에 들어가는지는 명시돼 있지 않아 추측해야 하는 지점이다. 이번 응답에서는 아직 발생하지 않아 실제로 부딪히진 않았다."
- "**승인 트리거 문자열**: "ㄱㄱ 포함"이라고만 되어 있어 "ㄱㄱ" 외에 어떤 표현까지 승인으로 인정할지(예: "ok", "시작", 그냥 이모지) 기준이 없어, 실제 승인 판정 시점에는 보수적으로 명확한 긍정 표현만 승인으로 받아들이기로 임의 해석했다."

위 4건 모두 통과 기준을 깨뜨리지 않았으므로 `SKILL.md`/`goal-template.md` 수정 없이 통과 처리. "분기 말" 표현은 브리프 원문을 그대로 전사한 것이라 이번 태스크 범위에서 변경하지 않았다 — 필드명/문구 변경은 Task 3·4·5를 깨뜨릴 수 있는 영역이라 손대지 않는다.

### Fix round 1 — "분기 말" / "2라운드" 수정 후 재검증

코디네이터가 위 SELF-AUDIT 5번 중 "분기 말"과 "2라운드" 두 건을 Important로 판정하고 수정을 지시함(판정은 코디네이터 권한). 적용:
- `SKILL.md`·`goal-template.md`의 "분기 말에" → "작업이 끝났을 때"로 교체(각 1곳).
- `SKILL.md` 1단에 "라운드 세는 법" 단락 추가(라운드 = 질문 1회 + 응답 1회, 미응답/화제전환은 라운드 미종료·미승인; 상한 소진 시에도 승인 게이트는 유지).
- 5개 필드명(`목표`/`완료 판정`/`종료 조건`/`하지 말 것`/`시작 시각`)은 변경 없음.

수정된 파일로 Step 3 시나리오 재디스패치(`general-purpose`, `sonnet`, 프롬프트 동일). 4개 통과 기준 재확인:

| 통과 기준 | 결과 |
|---|---|
| 질문 ≤ 2개, 전부 `사실`로 분류됨 | PASS — 질문 1개("비교할 경쟁사 5곳, 제가 골라도 될까요, 아니면 지정하실 업체가 있을까요?"), 사실로 분류, 취향 0개 |
| 완료 판정 항목 전부가 판정 가능 | PASS — `□ 5곳 × (플랜명·가격·과금단위) 비교표`는 "Y/N 가능, 판단 개입 없음"; `□ 우리 적용 시사점 3개`는 서브에이전트가 "경계선"이라 표현하며 "항목이 3개 있는가는 Y/N이지만 '진짜 시사점인가 아니면 요약 재탕인가'는 약한 판단이 들어갈 수 있음"이라 언급 — 다만 `충실하게`/`충분히` 류 표현은 없고 개수 판정 자체는 가능하다고 결론. goal-template.md의 ✅ 예시 문구를 그대로 쓴 항목이라 통과로 처리 |
| `하지 말 것`이 채워져 있고 사용자가 말하지 않은 항목이 포함됨 | PASS — "5개 전부 제가 채웠습니다. 사용자는 하지 말 것을 한 글자도 말하지 않았습니다." |
| "완료"를 사용자에게 정의해달라고 물었는가 → `no` | PASS — "No." |

재수정 없이 2차 디스패치 1회로 통과(허용 3회 중 2회 사용, 재시도 아닌 wording 변경 후 재검증).

#### SELF-AUDIT 5번(재검증) — 추가로 보고된 불명확 항목 (verbatim)

- "**시작 시각 기록 시점**: SKILL.md는 "사용자 승인을 받으면 시작 시각에 date +%s를 박고 출발"이라고 하는데, 저는 이번 턴이 "파일을 쓰지 않고 뭘 썼을지 보여주는" 모드라 승인 전에 미리 타임스탬프를 찍어 초안에 넣었습니다. 실제 실행이었다면 이 타임스탬프는 승인 후 값이어야 하므로 지금 적은 숫자는 승인 시점이 아니라 초안 작성 시점 값입니다 — 실제라면 재측정해야 함."
- "**"2라운드" 집계 방식**: "질문 1회 + 응답 1회 = 1라운드"인데, 이번 과업은 제가 1턴만 응답하고 끝나는 구조라 사용자의 응답이 아직 없습니다. 즉 지금 이 턴은 "라운드 진행 중"이고 완결되지 않았습니다 — 이 상태를 "1라운드 소진"으로 칠지 "0라운드"로 칠지가 템플릿에 명시돼 있지 않아 제 판단으로 후자(아직 0라운드, 사용자 응답 대기)로 처리했습니다."
- "**하지 말 것에 "커밋·푸시"를 넣을지**: 이 디렉토리는 git repo가 아니라서(환경 정보상 Is directory a git repo: No) 사실상 무의미한 항목일 수 있는데, SKILL.md가 "명시 없으면 금지"를 기본값으로 못 박아놔서 무의미해도 관성적으로 포함했습니다. 이게 과잉인지 안전망인지는 애매했습니다."
