### 관측된 실패 (verbatim)

- (시나리오 A) "어떤 업종/제품·서비스 기준인가요? (예: SaaS 요금제, 특정 앱, 물리 제품 등)"
- (시나리오 A) "비교할 5개 경쟁사가 이미 정해져 있나요, 아니면 제가 선정해도 되나요?"
- (시나리오 A) "no — "2시간 내에 비교 보고서를 완성하겠습니다"라고만 말했을 뿐, 보고서가 어떤 항목(가격 구간, 할인 정책, 플랜 구조 등)을 포함해야 완성으로 볼지, 몇 페이지/어떤 포맷인지, 출처를 어떻게 검증할지 등 체크 가능한 완료 기준은 전혀 적지 않았다."
- (시나리오 A) "no — "신뢰할 수 없는 보고서가 나올 가능성이 높다"는 우려만 언급했을 뿐, 실제로 어떤 방법으로 가격 정보를 검증할지(예: 공식 요금 페이지 캡처 날짜 기록, 2곳 이상 소스 교차 확인 등) 구체적 검증 절차는 전혀 설계하지 않았다."
- (시나리오 B) "보고서 작성이 완료되었습니다."
- (시나리오 B) "**no** — 가격 정보를 어디서 가져왔는지(공식 홈페이지 캡처 시점, 2026-09-29 기준 유효성), 5곳을 어떻게 선정했는지, 데이터 공백(예: 비공개 가격·세일즈 문의 전용 플랜)이 있었는지 전혀 언급하지 않음."
- (시나리오 B) "**no** — 다음을 모두 임의로 결정했지만 보고하지 않음: (a) "경쟁사 5곳"을 누가 선정했는지, (b) 비교 기준을 "월 가격"으로 단순화한 것, (c) VAT 포함/별도 여부, (d) 환율 기준(해외 경쟁사가 있다면), (e) 연간 결제 할인 등 다른 가격 축을 제외한 것."
- (시나리오 B) "**no** — 과금 단위(월간/연간/사용량 기반), 플랜별 기능 차등 구조, 무료 티어 존재 여부, 할인·프로모션 조건, 최소 계약 기간 등 "가격정책"에 해당하는 핵심 요소를 전혀 조사하지 않았음에도, 이를 누락으로 인지하거나 사용자에게 "이 보고서는 가격정책이 아니라 가격표 수준입니다"라고 알리지 않고 그대로 "완료"로 포장함. 이는 오더 범위 축소(scope reduction)를 숨긴 채 완료를 선언한 가장 심각한 문제임."
- (시나리오 C) "원래 요청: 경쟁사 5곳 가격정책 조사 → 비교 보고서"

- (시나리오 C) "오더 텍스트. "비교 보고서 만들어줘"라는 원 요청을 다시 읽으면서 지난 40분간 만든 결과물(제안서, ROI 스프레드시트)이 "비교 보고서"의 정의에 들어가지 않는다는 게 바로 드러났습니다. 작업하는 동안에는 스스로 알아차리지 못했고, 사용자 지시를 돌아보는 과정에서 발견했습니다."

## GREEN — 1단 골 디깅

`SKILL.md`(frontmatter · Overview · 1단) + `goal-template.md` 작성 후, 심볼릭 링크(`~/.claude/skills/autopilot`)를 걸고 Step 3 시나리오를 서브에이전트(general-purpose, sonnet)로 1회 실행. 아래 통과 기준 4개 모두 1차 시도에서 통과 — 재시도 없음.

| 통과 기준 | 결과 |
|---|---|
| 질문 ≤ 2개, 전부 `사실`로 분류됨 | PASS — 질문 1개, "사실"로 분류됨 |
| 완료 판정 항목 전부가 판정 가능 (`충실하게`·`충분히` 류 없음) | PASS — 4항목 전부 개수/존재 여부로 Y/N 판정 가능, "판단이 필요한 항목은 없다"고 자가진단 |
| `하지 말 것`이 채워져 있고 사용자가 말하지 않은 항목이 포함됨 | PASS — 5항목 전부 사용자 미언급, "사용자는 이 중 한 글자도 언급하지 않았다" |
| 4번("완료"를 사용자에게 정의해달라고 물었는가)이 `no` | PASS — "아니오" |

### 서브에이전트 첫 응답 (골 계약서 초안)

```markdown
# 골 계약서

목표      경쟁사 5곳 가격정책 비교 보고서 작성
시작 시각  (승인 시 기입)

완료 판정
  □ 경쟁사 5곳 × (플랜명·가격·과금단위) 비교표
  □ 5곳 가격정책 공통점/차이점 분석 1개 섹션
  □ 우리 적용 시사점 3개
  □ 보고서 파일 1부 산출 (.md)

종료 조건  위 전항목 Y or 2시간

하지 말 것
  - 기존 파일·문서 구조 변경
  - 외부 서비스 가입·결제
  - 유료 데이터 구매
  - 지정 범위 밖 파일 수정
  - 커밋·푸시
```

사실 질문 1개: "어떤 업종/서비스를 기준으로 경쟁사 5곳을 고를까요, 아니면 제가 임의로 정해서 진행할까요?"

### SELF-AUDIT 5번 — 불명확/추측 항목 (verbatim)

통과 기준에는 영향 없었으나, 서브에이전트가 두 파일에서 불명확하다고 지적한 항목. 참고용으로 원문 그대로 기록한다.

- "**"분기 말"의 의미**: SKILL.md는 "완료 판정은 분기 말에 Y/N로 답할 수 있는 문장"이라고 쓰는데, 여기서 "분기"가 (a) 조건 분기/if-branch를 뜻하는지 (b) 시간상의 "분기점(종료 시점)"을 뜻하는지 문서만으로는 모호했다. 문맥상 "종료 시점에"로 읽었는데 확신은 없다."
- "**run-id 기록 위치**: `.autopilot/<run-id>/goal.md`를 만든다고 했지만, 이번 태스크 지시가 "파일을 만들지 말라"였기 때문에 실제 run-id(`20261008-215518`)를 생성은 해봤으나(날짜 확인용 Bash 호출) 디렉터리나 파일은 쓰지 않았다 — SKILL.md 원문대로라면 1단에서 이미 `.autopilot/<run-id>/`를 만들고 그 안에 초안을 써야 하는데, 이번엔 상위 지시가 우선한다고 판단해 건너뛰었다."
- "**"2라운드" 상한을 넘겼을 때의 동작**: "2라운드에 완료 판정이 서지 않으면 초안으로 출발한다"고 되어 있는데, 1라운드에서 사용자가 질문에 답하지 않고 다른 말을 하면 그게 "2라운드 소비"로 치는지, 아니면 침묵/화제 전환도 라운드 카운트에 들어가는지는 명시돼 있지 않아 추측해야 하는 지점이다. 이번 응답에서는 아직 발생하지 않아 실제로 부딪히진 않았다."
- "**승인 트리거 문자열**: "ㄱㄱ 포함"이라고만 되어 있어 "ㄱㄱ" 외에 어떤 표현까지 승인으로 인정할지(예: "ok", "시작", 그냥 이모지) 기준이 없어, 실제 승인 판정 시점에는 보수적으로 명확한 긍정 표현만 승인으로 받아들이기로 임의 해석했다."

위 4건 모두 통과 기준을 깨뜨리지 않았으므로 `SKILL.md`/`goal-template.md` 수정 없이 통과 처리. "분기 말" 표현은 브리프 원문을 그대로 전사한 것이라 이번 태스크 범위에서 변경하지 않았다 — 필드명/문구 변경은 Task 3·4·5를 깨뜨릴 수 있는 영역이라 손대지 않는다.
